# 5. AI・データ活用の社会実装とプロジェクトの進め方

## 5-1 | AI プロジェクトの体制・進め方・契約

### プロジェクトのロール

- **データサイエンティスト**: ビジネス課題をデータ分析・統計・機械学習で解く専門職。
- **AIエンジニア / 機械学習エンジニア**: モデルの設計・実装・チューニングを担当。
- **データエンジニア**: データ収集・蓄積・前処理パイプラインの基盤構築。
- **MLOpsエンジニア**: モデルのデプロイ・運用・監視を担当。
- **プロダクトマネージャ (PdM)**: 要件定義・優先度付け・ステークホルダー調整。
- **ステークホルダー**: 顧客・経営層・現場部署など、プロジェクトに関わる利害関係者全般。

### 契約種別

- **準委任契約**: 特定の業務を遂行することを定めた契約。業務や成果物の完成の義務を負わない。AI/PoCは精度保証が困難なため**原則こちら**。
- **請負契約**: 委託された業務を完成し、成果物を納品することを定めた契約。完成責任あり。
- **NDA (Non-Disclosure Agreement, 機密保持契約 / 秘密保持契約)**: プロジェクトを開始する前に締結する、第三者への情報の漏洩または不正利用を防止するための契約。
- **「AI・データの利用に関する契約ガイドライン」**: 経済産業省によるガイドラインで、**探索的段階型**のソフトウェア開発方式が推奨されている。開発のプロセスを **アセスメント → PoC → 開発 → 追加学習** の4段階に分ける。
- **生成AIの利用ガイドライン**: 一般社団法人日本ディープラーニング協会 (JDLA) などが公開。社内利用ルールの雛形。

### 開発プロセス

- **PoC (Proof of Concept, 概念実証)**: 新しい仕組みやアイデアの実現可能性や期待された精度を達成できるかを検証するためのプロジェクト・フェーズ。
- **ウォーターフォール開発**: はじめにシステム全体の設計と計画を固めて、それに従って全ての要件・機能を一気に上流から下流に向けて実装する開発様式。
- **アジャイル開発**: 「計画→設計→実装→テスト」といった開発工程を小さい機能単位に分割し、機能単位ごとにサイクル（イテレーション）を繰り返す開発様式。AI開発と相性が良い。
- **CRISP-DM (Cross-Industry Standard Process for Data Mining)**: 様々な業界で適用可能なデータマイニングの方法論。**Business Understanding → Data Understanding → Data Preparation → Modeling → Evaluation → Deployment** の6フェーズから構成される。各フェーズ間を反復する循環型。
- **MLOps (Machine Learning Operations)**: 機械学習の開発担当と運用担当が連携しながらモデルの開発から運用までの一連を管理する体制。DevOps の ML 版。

### プロジェクトマネジメント

- **KPI (Key Performance Indicator)**: 目標達成度を測る重要業績評価指標。
- **KGI (Key Goal Indicator)**: 重要目標達成指標（最終ゴール）。
- **AIキャンバス**: AIプロジェクトの目的・データ・予測内容・効果などを1枚のシートに整理するフレームワーク。
- **BPR (Business Process Re-engineering)**: 業務プロセスの抜本的再設計。AI導入の前提として既存業務の見直しを行う。
- **プライバシー・バイ・デザイン (PbD)**: 設計段階からプライバシー保護を組み込む考え方。
- **セキュリティ・バイ・デザイン**: 設計段階からセキュリティを組み込む考え方。
- **責任分担 (RACI)**: Responsible（実行者）/ Accountable（説明責任者）/ Consulted（協議先）/ Informed（情報共有先）の役割マトリクス。

## 5-2 | DXを支えるビッグデータと諸技術

### DX・データ活用の概念

- **デジタルトランスフォーメーション (DX)**: 事業のあり方、ビジネスモデルやサービス形態の根本的かつ大局的な「デジタルによる変容」を目指す概念。
- **オープンイノベーション**: 製品、サービス、技術の開発や組織改革などにおいて、社外の組織から知識や技術を取得し社内に取り込むことで、自前主義からの脱却を図る。
- **ビッグデータ**: 生成速度と更新速度が非常に速い大規模なデータ。
  - **3V**: **Volume**（量）、**Variety**（多様性）、**Velocity**（速度・頻度）
  - **5V**: 3V + **Veracity**（正確性・信ぴょう性）、**Value**（価値）
- **オープンデータ**: 二次利用を許可した上で公開され、誰でも自由に活用できるデータ。政府や自治体の統計データなど。

### データの種類・形式

- **構造化データ**: 行と列が定義されている、表形式のデータ。例: CSV、Excel、RDB（リレーショナルデータベース）。
- **半構造化データ**: タグや階層構造はあるが、行列の表形式ではないデータ。例: **JSON、XML、HTML**。
- **非構造化データ**: 構造や規則性が明確に定まっていないデータ。例: 画像、音声、動画、フリーテキスト。ビッグデータのうち、非構造化データは構造化データよりも発生頻度が高い。

### データ基盤

- **データレイク (Data Lake)**: 構造化・半構造化・非構造化を問わず、生データのまま大量に蓄積するストレージ。
- **データウェアハウス (DWH, Data Warehouse)**: 分析用に整形・統合された**構造化データ**の倉庫。例: BigQuery, Snowflake, Redshift。
- **データマート (Data Mart)**: DWHから特定の用途・部門に合わせて切り出した小規模なDB。
- **ETL (Extract / Transform / Load)**: 抽出 → 変換 → 格納。古典的なバッチ統合。
- **ELT (Extract / Load / Transform)**: 抽出 → 格納 → 変換。クラウドDWH時代の主流。

### IoT・自動化技術

- **IoT (Internet of Things, モノのインターネット)**: 身の回りのもの（電気製品、センサーなど）をインターネットに接続することで、データが生成され、そのデータを分析などに利用できること。
- **RPA (Robotic Process Automation)**: コンピュータやソフトウェアロボットを通じて事務的な作業を自動化・効率化すること。生産性向上、工数削減、誤作動防止などの効果が期待できる。
- **5G**: 第5世代移動通信。**高速・低遅延・多接続**で IoT/エッジAI の基盤に。
- **デジタルツイン (Digital Twin)**: 現実世界の物理対象をデジタル空間に再現し、シミュレーション・予測する技術。
- **コネクテッドカー**: 通信機能を備え車外と情報をやり取りする自動車。
- **自動運転レベル (0〜5)**: SAE 定義。0=手動、1=運転支援、2=部分自動、**3=条件付き自動（責任は運転者→システム移行）**、4=高度自動、5=完全自動。

### 産業応用・社会実装

- **Society 5.0**: 日本政府が掲げる「**サイバー空間とフィジカル空間を高度に融合**した人間中心の社会」。狩猟→農耕→工業→情報→Society 5.0。
- **インダストリー 4.0 (Industrie 4.0)**: ドイツ発の第4次産業革命。IoT/AI による製造業のスマート化。
- **スマートシティ**: ICT/AI を活用した持続可能な都市運営。
- **スマートファクトリー**: 工場の IoT/AI 化による生産最適化。
- **MaaS (Mobility as a Service)**: 移動手段をサービスとして統合提供。

## 5-3 | AI開発の環境・基盤

### 開発環境・ソフトウェア

- **BI (Business Intelligence) ツール**: ノンプログラミングで多角的にデータを集約・整理し、可視化することで、ビジネスに有益な情報を抽出するのに使うソフトウェアツール。例: Tableau, Power BI, Looker。
- **API (Application Programming Interface)**: ソフトウェアやプログラムの一部を公開し、他のコンピュータやソフトウェアと機能を共有するためのインターフェイス。
- **オープンソース (OSS)**: 公開され誰でも改変・再配布可能なソフトウェア。例: TensorFlow, PyTorch, scikit-learn。

### クラウド・運用形態

- **クラウド (クラウドコンピューティング)**: 手元にインフラを用意せずにインターネットを経由してサービスやリソース（データベース、サーバ、ネットワーク、アプリケーションなど）を必要な時に必要な量だけ利用する仕組み。
- **オンプレミス (On-Premise)**: システムを運用する上で必要なソフトウェアやハードウェアを自社内で保有し管理する運用形態。
- **エッジAI (Edge AI)**: システムの末端に位置するデバイスに直接搭載し、そのデバイスの上で実行されるAI。**低遅延・通信負荷軽減・プライバシー保護**に有利。
- **エッジコンピューティング**: ネットワークの端（デバイス側）でデータ処理を行う設計思想全般。エッジAIはこの一部。
- **主要クラウドプロバイダ**: **AWS**（Amazon）、**Azure**（Microsoft）、**GCP**（Google Cloud Platform）が3大プロバイダ。

### サービスモデル

- **SaaS (Software as a Service)**: ソフトウェア、アプリケーションの機能を、インターネット経由で提供するクラウドサービス。例: Gmail, Salesforce。
- **PaaS (Platform as a Service)**: アプリケーションが稼動するプラットフォーム（OS、ミドルウェア）を提供するクラウドサービス。例: Heroku, Google App Engine。
- **IaaS (Infrastructure as a Service)**: ネットワーク、サーバ(CPU・GPU、メモリ・ストレージ)などのコンピューティングリソースを提供するクラウドサービス。例: Amazon EC2, Compute Engine。
- **MLaaS (Machine Learning as a Service)**: 機械学習機能をクラウド経由で提供。例: AWS SageMaker, Azure ML, Vertex AI。

### コンテナ・基盤技術

- **Docker**: 開発者やシステム管理者がコンテナ(仮想的なユーザ空間)という単位でアプリケーションを構築、実行、共有するためのプラットフォーム。**コンテナ型仮想化**と呼ばれる技術が使用される。仮想マシンより軽量。
- **Kubernetes (K8s)**: コンテナのオーケストレーション（自動デプロイ・スケール・管理）。Google発、現在は CNCF が管理。
- **ブロックチェーン (Blockchain)**: 中央管理者を必要としない自律分散システムで、分散的に管理された複数のコンピュータをネットワークに接続し、暗号化されたデータのコピーを全端末で共有している仕組み。システムの可用性と完全性が保たれやすい。

### MLOps・自動化

- **MLOps (Machine Learning Operations)**: 機械学習の開発担当と運用担当が連携しながらモデルの開発から運用までの一連を管理する体制。DevOps の機械学習版。
- **CI/CD (Continuous Integration / Continuous Delivery)**: 継続的インテグレーション/デリバリ。テストとデプロイの自動化。
- **DevOps**: 開発 (Development) と運用 (Operations) の連携・自動化文化。
- **AutoML (Automated Machine Learning)**: 特徴量選択・モデル選択・ハイパーパラメータ調整を自動化する技術。
- **NAS (Neural Architecture Search)**: ニューラルネットワークの構造そのものを自動探索する手法。AutoML の一部。

## 5-4 | データ収集・前処理

- **アノテーション (Annotation, ラベリング)**: 機械学習用にデータへ正解ラベルを付与する作業。教師あり学習の前提。
- **クラウドソーシング (Crowdsourcing)**: 不特定多数の作業者にネット経由でアノテーションを委託する仕組み。例: Amazon Mechanical Turk。
- **データ拡張 (Data Augmentation)**: 既存データに変換（回転・反転・切り抜き・ノイズ等）を加えてデータ量を水増しする手法。詳細は[3章](3-ディープラーニングの仕組みと応用.md)参照。
- **データクレンジング (Data Cleansing)**: 重複・誤記・欠損などのノイズを取り除き、データ品質を整える前処理。
- **欠損値処理**: 削除（リストワイズ削除）、平均値/中央値補完、回帰補完、多重代入法など。
- **外れ値処理**: 明らかな異常値を除外・修正する。3σ ルール、IQR ルールなど。
- **特徴量エンジニアリング (Feature Engineering)**: 元データから機械学習に有効な特徴量（説明変数）を作り出す作業。深層学習では自動化される傾向。
- **特徴量ストア (Feature Store)**: 学習・推論で再利用可能な特徴量を一元管理する基盤。
- **公開データセット**: **ImageNet**（画像分類, 1400万枚）、**MNIST**（手書き数字）、**COCO**（物体検出・セグメンテーション）、**CIFAR-10/100**、**SQuAD**（質問応答）、**WikiText**、**LibriSpeech**（音声）など。
- **合成データ (Synthetic Data)**: シミュレーション・生成AIで人工的に作るデータ。プライバシー保護や少データ補完に有用。

### データ活用の例（適法・適切な利用パターン）

AIプロジェクトにおける**データ活用の例**を、法律・倫理の観点から整理する。

| データ活用の例 | データ出所 | 適法性の根拠 | 留意点 |
|---|---|---|---|
| **ImageNetからデータをダウンロード**して画像分類モデルを学習 | 学術研究目的の公開データセット（Princeton/Stanford） | **著作権法 第30条の4**（情報解析目的の利用は許諾不要） | ライセンス条件（研究用途限定など）の遵守。商用利用可否はデータセットごとに異なる |
| **政府が調査、集計、公開している人口動態データ**を分析に利用 | **政府統計（e-Stat）・厚生労働省人口動態統計**等の**オープンデータ** | **オープンデータ**として政府が二次利用を許可（**政府標準利用規約**、原則 CC BY 互換） | 出典の明記、最新版への追従 |
| **DBpediaから抽出した構造化データ**を、**大学のデータサイエンス講義で講師が利用** | **DBpedia**（Wikipediaから抽出した**Linked Open Data, LOD**） | **CC BY-SA ライセンス**で公開。教育・研究目的での利用に親和的。著作権法上も**学術研究例外**および**第30条の4**で広く認められる | 出典・ライセンス継承（SA: 同一条件継承）に注意 |
| **クラウドソーシング**でアノテーションを依頼 | Amazon Mechanical Turk 等 | 通常の業務委託契約 | 個人情報を含むデータは作業者に開示しない設計、品質管理 |
| **合成データ**で学習データを補完 | シミュレータ・生成AIによる人工データ | 個人情報・著作権の制約を回避できる | 実データとの分布乖離、合成バイアスに注意 |

#### 関連する法的根拠

- **著作権法 第30条の4**：**情報解析目的**であれば、著作物を**著作権者の許諾なく**利用可能。AI学習・統計分析が該当（→ [6章](6-法規制・倫理ガイドライン・社会問題.md#6-3--著作権)）。
- **オープンデータ政策**：政府データは**機械判読可能・二次利用可能**な形式での公開を原則化（**官民データ活用推進基本法**、政府CIOポータル）。
- **e-Stat**：政府統計の総合窓口。人口動態、国勢調査、家計調査、経済統計など。
- **DBpedia / Wikidata**：Wikipediaから構造化データを抽出した**Linked Open Data (LOD)**。SPARQL で問合せ可能。
- **学術研究目的の例外**：個人情報保護法でも、学術研究機関による利用は一定の例外規定あり。

#### ※ 不適切な「データ活用の例」

- 個人情報を**本人同意なく**機械学習に用いる（要配慮個人情報なら特に違反）。
- 著作権者の**「享受目的」**で著作物をAI学習させる（第30条の4の例外に該当しNG）。
- 営業秘密・限定提供データを**不正取得**して活用する（不正競争防止法違反）。
- **オプトアウト**で取得した個人データを、要配慮個人情報を含む形で再提供する。

## 5-5 | モデル運用・MLOps の実務

- **データドリフト (Data Drift)**: **入力データの分布**が時間とともに変化する現象。
- **コンセプトドリフト (Concept Drift)**: **入力と出力の関係（決定境界）**が時間とともに変化する現象。
- **再学習 (Retraining)**: ドリフトに対応してモデルを最新データで再訓練すること。
- **継続学習 (Continual Learning)**: 過去の知識を保持しながら新しいデータを学習する。**破滅的忘却 (Catastrophic Forgetting)** が課題。
- **AB テスト**: 2 つのバージョン (A/B) を並行運用し、効果を比較する手法。
- **シャドーデプロイ (Shadow Mode)**: 新モデルを本番トラフィックで動かしつつ、出力はユーザに見せず比較・検証する。
- **カナリアリリース (Canary Release)**: 新バージョンを一部ユーザに先行公開し、徐々に展開する。
- **モデルカード (Model Card)**: モデルの目的・性能・制限・想定外の使い方・バイアスを記述するドキュメント。Google が提唱。
- **データシート (Datasheet for Datasets)**: データセットの来歴・収集方法・用途・偏りを記述するドキュメント。
- **モデルレジストリ (Model Registry)**: 学習済みモデルをバージョン管理する仕組み。例: MLflow。
- **モニタリング (Monitoring)**: 推論結果の精度・遅延・データ分布を継続監視。

## 5-6 | AI 利活用に関わる留意点

- **公平性 (Fairness)**: 学習データの偏りが特定属性への差別を生まないよう配慮する。詳細は[6章](6-法規制・倫理ガイドライン・社会問題.md)参照。
- **説明可能性 (Explainability) / XAI**: モデルの判断根拠を人が理解できる形で示す。
- **トレーサビリティ**: 学習データ・モデル・推論結果の来歴を追跡可能にする。
- **データ品質 (Veracity)**: 不正確・重複・偏りのあるデータが意思決定を歪めるリスク。
- **AI ガバナンス**: AI 利用に関わるリスクを組織として統制する仕組み。

詳細な法規制・倫理は [6-法規制・倫理ガイドライン・社会問題](6-法規制・倫理ガイドライン・社会問題.md) を参照。

## ※よくある誤解・混同注意

- **準委任契約 vs 請負契約**
  概要：前者は業務遂行（成果物の完成義務なし）、後者は成果物の納品義務あり。
  混同注意：AI開発は精度保証が困難なため**準委任が原則**。

- **ウォーターフォール vs アジャイル**
  概要：前者は上流から下流に一括、後者は小単位を反復。
  混同注意：AI/PoC は要件が固まらないので**アジャイル親和性が高い**。

- **SaaS vs PaaS vs IaaS**
  概要：抽象度の階段。SaaS（アプリ）> PaaS（実行環境）> IaaS（インフラ）。
  混同注意：「OS まで提供される」=PaaS、「サーバそのものを借りる」=IaaS、「メールアプリを使う」=SaaS。

- **データレイク vs データウェアハウス (DWH)**
  概要：前者は生データ（構造不問）、後者は整形済み構造化データ。
  混同注意：「非構造化データも入る大量保管庫」=データレイク。「分析用に整形済み」=DWH。

- **ETL vs ELT**
  概要：変換のタイミングが格納の前か後か。
  混同注意：クラウドDWH（BigQuery/Snowflake等）は計算リソースが豊富なので **ELT** が主流。

- **データドリフト vs コンセプトドリフト**
  概要：前者は**入力分布**の変化、後者は**入力と出力の関係**の変化。
  混同注意：「ユーザ層の変化で入力傾向が変化」=データドリフト。「正解ラベルの定義自体が変わる」=コンセプトドリフト。

- **構造化 vs 半構造化 vs 非構造化**
  概要：行列形式（CSV/RDB）/ タグや階層構造あり（JSON/XML/HTML）/ 形式自由（画像/音声/動画/フリーテキスト）。
  混同注意：JSON・XMLは**半構造化**。CSVは**構造化データ**。

- **エッジAI vs エッジコンピューティング**
  概要：前者は端末上でAIを実行、後者は端末側で処理を行う設計思想全般。
  混同注意：エッジAIはエッジコンピューティングの**部分集合**。

- **CRISP-DM vs MLOps**
  概要：CRISP-DMはデータマイニングの**プロセス論**（1990年代）、MLOpsは機械学習の**運用体制**（DevOps×ML）。
  混同注意：CRISP-DMは6フェーズ反復で**モデル運用後の継続的改善**を主目的としない。MLOpsはデプロイ後のモニタリング・再学習まで含む。

- **AB テスト vs シャドーデプロイ vs カナリアリリース**
  概要：A/B = 2系統並行比較、シャドー = 新系統は本番トラフィックを処理するが結果はユーザに出さない、カナリア = 一部ユーザに段階公開。
  混同注意：「ユーザに影響を与えずに新モデルを検証」=**シャドー**。「一部ユーザだけ新版」=カナリア。
